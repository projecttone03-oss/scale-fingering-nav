# アプリ設計書：スケール運指ナビ（仮称）

がくふ工房「管楽器奏者のための基礎トレーニング」対応 Webアプリ
Claude Code による実装のための詳細設計 ― v1.0（2026-09-13）

---

## 0. この文書の使い方

この設計書は、Claude Code にそのまま渡して実装を進めるための仕様です。リポジトリ直下に `docs/SPEC.md` として置き、`CLAUDE.md` から参照させることを想定しています。

各章の位置づけは次のとおりです。1〜3章が「何を作るか」（決定事項・画面・機能）、4〜8章が「どう作るか」（データ・描画・音・同期・構成）、9〜11章が「どの順で作り、どう確かめるか」です。実装中に仕様の解釈で迷ったときは、**PDF「基礎トレーニング」の記載を正**とします（詳細は 4.1）。

## 1. 確定している前提・決定事項

| 項目 | 決定内容 |
|---|---|
| 対象教材 | がくふ工房「吹奏楽 基礎練習｜管楽器奏者のための基礎トレーニング」（PDF・全15楽器） |
| アプリの役割 | PDF掲載の全24調スケールを、メトロノームと参考音に合わせて「今の音／次の音」の楽譜（五線譜のハイライト）と運指を表示する |

| アクセス制限 | **なし**。誰でも使える公開 Web アプリ。購入者への案内は SD カード同梱のQRコード |
| 配布 | Web（PWA）。GitHub Pages でホスティング。初回アクセス後はオフライン動作 |
| 想定デバイス | **縦向きスマートフォンを基本**。タブレット（縦・横）でも崩れない。PC は「使えれば良い」 |
| 楽譜表示 | 連続スクロールはしない。**2段の静止表示**（上行8音／下行8音）＋現在音・次音のハイライト |
| いま／つぎ枠 | 「今の音の音名＋運指」の右隣に「次の音の音名＋運指」を常時表示（**必須要件**）。音の高さは五線譜のハイライトで示す（枠の中の楽譜断片は M4 の実機確認で廃止） |
| 参考音 | スケールの各音を正しい実音で鳴らす機能は**コア機能**（ON/OFF可） |
| 音価 | PDF は全音符表記だが、アプリでは 全音符／二分音符／四分音符 を選択可（既定＝二分音符）。将来のリズムパターン拡張に備え、音価は可変設計 |

| 運指データの正 | 金管・トロンボーンは PDF 記載の運指番号／ポジションを正とする。木管は楽器メーカー公式運指表を突き合わせ先とする |
| 開発順序 | **B♭トランペット×ハ長調で最後まで動くもの**を先に作り、その後データを増やす |
| 商品ページ掲載 | メルカリは動画不可のため、スクリーンショットを掲載（本設計の対象外） |

## 2. 画面仕様

### 2.1 画面一覧

| ID | 画面 | 役割 |
|---|---|---|
| S1 | 楽器選択 | 15楽器から1つ選ぶ。初回起動時に表示。選択は端末に保存 |
| S2 | メイン（練習） | 調・テンポ等の設定、楽譜、いま／つぎ枠、再生制御。アプリの主画面 |
| S3 | 運指拡大（モーダル） | いま／つぎ枠をタップしたとき、運指図を画面いっぱいに表示 |
| S4 | 情報（モーダル） | アプリの説明、教材「基礎トレーニング」の紹介、がくふ工房の表記、不具合報告フォームへのリンク |

画面遷移は S1 → S2 が基本。S2 のヘッダー「楽器名」をタップすると S1 に戻る。S3/S4 は S2 の上に重なるモーダルで、閉じると S2 の状態（選択した調・再生位置）は保持される。

### 2.2 S1 楽器選択

15楽器を PDF と同じ順に縦一列のリストで表示する（1行＝楽器名＋短い補足）。

```
ピッコロ / フルート / オーボエ / ファゴット /
B♭クラリネット / バスクラリネット /
アルトサックス / テナーサックス / バリトンサックス /
B♭トランペット / Fホルン / トロンボーン / ユーフォニアム / チューバ /
ストリングベース
```

未実装フェーズの楽器は「準備中」と表示し、タップ不可にする（データが揃った楽器から順に有効化）。

### 2.3 S2 メイン画面のレイアウト（縦向きスマホ基準）

上から順に4ブロック。縦 812px（iPhone 標準）で全ブロックがスクロールなしに収まることを目標にする。

```
┌──────────────────────────────┐
│ ヘッダー（48px）                    │  楽器名（タップで S1）／ i ボタン（S4）
├──────────────────────────────┤
│ 設定行（約 96px）                   │  調セレクト／テンポ／音価／音ON-OFF
├──────────────────────────────┤
│ 五線譜 2段（約 200px）              │  上行8音・下行8音、現在音＝濃色、次音＝淡色
├──────────────────────────────┤
│ いま／つぎ 枠（約 300px）           │  左：いま（大） 右：つぎ（やや小）
│   ┌──────────┐ ┌────────┐         │  各枠＝ 音名＋運指図
│   │  いま     │ │  つぎ   │         │
│   └──────────┘ └────────┘         │
├──────────────────────────────┤
│ 再生バー（64px）                    │  ▶ 再生／■ 停止（トグル）、進行 "5 / 16"
└──────────────────────────────┘
```

タブレット・横向き（幅 ≥ 768px）では、五線譜ブロックと いま／つぎ枠を左右に並べる 2 カラムにする。ブレークポイントは 768px の1つだけとし、それ以外は流動レイアウトで対応する。

### 2.4 設定行の各コントロール

| コントロール | 仕様 |
|---|---|
| 調 | `<select>`。表示は「ハ長調 (C Major)」形式。並び順は PDF と同じ（長調12→短調12）。**実音の調**を選ぶ |
| テンポ | 数値入力（40〜160 BPM、既定 60）＋「−5 / +5」ボタン。四分音符＝1拍 |
| 音価 | セグメントボタン 3択：全音符（4拍）／二分音符（2拍・既定）／四分音符（1拍） |
| 参考音 | トグル：ON（既定）／OFF。OFF のときはメトロノームのクリックのみ |
| 再生 | 再生中はボタンが「停止」に変わるトグル。再生中は 調・音価 を変更不可（テンポ・参考音は変更可） |

### 2.5 五線譜ブロック

- 2段。上段＝上行の8音（主音〜オクターブ上の主音）、下段＝下行の8音（オクターブ上の主音〜主音）。最高音は上段の最後と下段の最初の2か所に描き、2回鳴らす（PDF と同じ）。
- 各段の左端に音部記号と調号。上段は調号の右に拍子記号 4/4。音符は 5.7 の間隔で配置し、4拍ごとに小節線、下段の最後に終止線（5.6）。
- 再生前：全音符が通常色。
- 再生中：現在音を **濃色＋背景ハイライト**、次の音を **淡色ハイライト**。カウントイン中は開始位置の音（先頭から再生なら1音目）が「次の音」として淡色になる。
- 音符の形は選択した音価に従う（全音符＝白抜き符頭のみ／二分音符＝白抜き＋符幹／四分音符＝塗り＋符幹）。
- **音を選ぶ（開始位置・運指の予習）**：停止中だけ受け付ける（再生中・カウントイン中は受け付けない）。選んだ音は「いま」に表示し（次の音が「つぎ」）、五線譜ではその音を「現在」、次の音を「次」としてハイライトする。再生はこの音から始まる（2.7）。
  - 五線譜のカーソル：五線譜のどこかに触れると、指の位置に縦のバーが出る。指を左右に動かすとバーが追従し、バーと重なった位置の音（音符と音符の間では範囲が近いほうの音、音部記号・調号の上では最初の音）が選ばれて、「いま」枠にその音の運指が出る。指を離すとその音が開始位置として確定し、バーは消える。上段・下段のどちらでも、指のある段で選ぶ（指が段の外に出ても近いほうの段）。音符を正確に狙わなくてよいので、楽器を持ったままでも操作しやすい（M4 の実機確認で、音符のタップは小さくて反応しないことが多かったため、この方式にした）。
  - バーは現在音の色（`--note-current`、不透明度 0.75）、太さ `0.8S`（375px 幅の画面で約 5.5px）、長さは音符のハイライトの背景と同じ（段の上端から `1S`〜`11S`）。システムの操作などで指の操作が取り消されたときは、触れる前の選択に戻す。
  - 再生バーの ◀ ▶（44px）と、いま／つぎ枠の左右のスワイプ（2.6）でも、前後の音に動かせる。次へ：未選択なら1音目、16音目ではそのまま。前へ：1音目より前は未選択（先頭から、「いま」は「▶で開始」）に戻す。
  - 再生が終わって最終音が残っている（done）ときに選ぶと、停止中に戻してから選ぶ。調を変えたら選択を解除する。
- 再生中（カウントインを含む）は、メトロノームの拍に合わせて、現在音の背景ハイライト（カウントイン中は開始位置の音の淡色ハイライト）を濃くする（脈動。7.2）。拍の頭で最も濃く、拍の半分までに元に戻る。`prefers-reduced-motion: reduce` のときは動かさない。

### 2.6 いま／つぎ枠

| | いま（左） | つぎ（右） |
|---|---|---|
| 幅 | 枠エリアの 54% | 枠エリアの 43%（枠の間のすき間 3%） |
| 内容 | 音名（例 `D5`、日本式は使わない）／運指図 | 同じ構成をやや小さく |
| 再生前 | 空（「▶で開始」）。音を選んでいればその音 | 1音目。音を選んでいればその次の音 |
| 最終音 | 16音目 | 「おわり」 |
| 音の切替時 | 枠の中身が 120ms でスライド（前の音が左へ出ていき、次の音が右から入る。枠の中だけで動く） | 同じ |
| 拍 | 再生中（カウントインを含む）は、枠線をメトロノームの拍に合わせて太く濃くする（脈動。7.2） | |
| スワイプ | 停止中、枠の上で左へスワイプすると次の音、右へスワイプすると前の音を選ぶ（2.5） | 同じ |
| タップ | S3 で拡大 | S3 で拡大 |

代替運指（`isPrimary: false`）の表示は、設定「別の運指を表示」（既定オフ）で切り替える。

- オフ（既定）：主運指だけを表示する。いま／つぎ枠に「別の運指あり」を出さず、S3 に「標準／別」の切り替えボタンを出さない。
- オン：代替運指がある音は、運指図の下に「別の運指あり」の小ラベルを出し、S3 の拡大表示で切り替えられる。
- `hidden: true` の代替運指（4.6。B♭トランペットの第7倍音の運指 E5＝123、F5＝13、F♯5＝23、G5＝12、G♯5＝1、A5＝2、B♭5＝0）は、オンでも表示しない。音程が低くなり、生徒が混乱するため。データには残す。表示する代替運指が残らない音（例 G♯5）は、オンでも「別の運指あり」を出さない。
- 設定は端末（localStorage）に保存し、次回起動時も維持する（7.4）。設定項目の置き場所は M5 の設定画面。M5 までは開発用ページ `dev/s2.html` のヘッダーで切り替える。

実装（`src/render/nowNext.ts`、M4）：

- 枠の中は上から「音名・運指図（主運指）」、運指図のすぐ下に「別の運指あり」（設定がオンのときだけ）。枠の高さの中に均等に配置する。楽譜断片は置かない（M4 の実機確認で、小さすぎて読めなかったため廃止。音の高さは上の五線譜のハイライトで分かる）。
- 運指図は枠の幅いっぱいに描く（図の大きさは枠の幅で決まる）。そのため枠の左右の余白は最小（2px）にし、枠の幅は いま 54%／つぎ 43% とした（楽譜断片を削ったときに、つぎの運指図を大きくするため 55%／40% から変更）。音名は いま `3rem`、つぎ `2.4rem`。「別の運指あり」の行は、出さないときも高さを取る。
- 375×812 では、B♭トランペットの運指図の円の直径は「いま」約 49px（番号 約 27px）、「つぎ」約 38px（番号 約 22px）。音名は「いま」48px、「つぎ」38px。
- 音名は記譜の綴りを ♯・♭・𝄪・𝄫 で書く（例 `F♯4`、`B♭4`）。カウントイン中の「いま」は「カウント」。
- 停止中に選んだ音（2.5）があれば、その音を「いま」、その次の音を「つぎ」にする。カウントイン中の「つぎ」は開始位置の音。
- スワイプ：枠の上で指を横に 40px 以上動かし、縦の動きの 1.5 倍より大きければスワイプ（左へ＝次の音、右へ＝前の音）。それより短い動きはタップ（S3）。スワイプしたあとのタップの判定では S3 を開かない。停止中だけ受け付ける。
- 動かすのは「つぎ」だった音が「いま」に移ったときだけ（カウントイン→最初の音、音 i → i+1、選んだ音を次の音へ進めたとき）。離れた音を選んだときや調を変えたときは、すぐ切り替える。
- スライドの作り（`mountNowNext` の `transition` は既定 `slide`）：前の中身をそのまま複製して枠の中に重ね（`position: absolute; inset: 0`）、それを 120ms で左へ 100% 動かして外し、新しい中身は右 100% の位置から 120ms で元の位置へ動かす。動かすのは `transform` だけで、枠の外へ出る部分は見えない（枠の中身は `overflow: hidden`）。`prefers-reduced-motion: reduce` のときはアニメーションなしで、すぐ切り替える。
- **見せ方の比較（M4、実機で決定）**：切り替わった感じが分かりやすい見せ方を、3案を同時に動かす比較ページ（`dev/transitions.html`）で実機比較し、**案3 のスライドに決めた**。
  - 案1 `crossfade`：前の中身を同じ位置で薄くし、新しい中身を浮かび上がらせる。→ 運指が切り替わった感じが弱かった。
  - 案2 `valves`：中身はすぐ入れ替え、押す・離すが変わったバルブだけが 1.2 倍にふくらんで戻る（変わらないバルブは動かない。円どうしの間隔は直径の 0.25 倍なので、1.25 倍を超えると隣とくっつく）。→ 採用しなかった。
  - 案3 `slide`（採用）：上のとおり。以前のスライド（「つぎ」枠の位置から動かす）は中身が枠の外にはみ出して見えたが、枠の中だけで動かすことで解決した。
  - 3案とも 120ms で、動かすのは `opacity` と `transform` だけ。音の予約・`progress` の計算には関わらない（7.2 と同じ考え方）。3案を同時に動かしても、再生中の 25ms のタイマーの遅れは動かさないときと変わらなかった（PC の Chromium で確認）。比較ページは他の見せ方を試すときのために残す。
- S3（`src/ui/modals.ts`）はタップした枠の音を開く（再生が進んでも、開いている間は同じ音のまま）。見出しは「いま　B4」のように枠と音名、運指図を大きく描き、その下に運指の説明（例「バルブ 1・3」）。表示する運指が2つ以上ある音（「別の運指を表示」がオンのときだけ）は切り替えボタン（主運指「標準」、代替「別」。金管は PDF と同じバルブ番号を添えて「標準　2」「別　13」）を出す。× ボタン・背景のタップ・Esc で閉じる。

### 2.7 再生の流れ

1. 再生ボタン → AudioContext を（初回は）ユーザー操作内で生成・resume する（iOS 対策）。
2. **カウントイン 1小節（4拍）**：クリックのみ。1拍目はアクセント。途中の音から始めるときも毎回4拍。
3. 開始位置の音から順に、各音を「音価×拍」の長さで進行。参考音 ON なら各音の開始時に実音を鳴らす。開始位置は停止中に選んだ音（2.5）で、選んでいなければ1音目。
4. 16音目が終わったら自動停止（途中から始めても、最後まで行ったら終わる。頭に戻って一周しない）。「いま」に最終音を残し、「つぎ」は「おわり」。選んだ音はそのまま残り、もう一度再生するとその音から始まる。
5. 停止ボタン → 即時停止。スケジュール済みの音はキャンセル。位置は選んだ音（選んでいなければ先頭）に戻す。鳴っている途中の音をいきなり切るとプツッと鳴るので、10 ms で音量を 0 にしてから止める。
6. 進行の表示「n / 16」は五線譜の位置で数える（6音目から始めたら「6 / 16」→「16 / 16」）。停止中は選んだ音の位置（選んでいなければ「– / 16」）、カウントイン中は開始位置、再生中は今の音、終了後は「16 / 16」。

## 4. データ設計

### 4.1 データの「正」と転記方針

- **楽譜データ（各楽器・各調の16音）は PDF から転記する。** 楽器ごとに出発音のオクターブが違うため、計算で生成せず転記する。ただし検証スクリプト（10.2）で「転記した音列が、実音の調から理論的に導かれる音列と一致するか」を機械的に確認する。
- **運指データ**は音高（MIDI 番号）をキーにする。同じ音高なら綴り（C♯/D♭）が違っても運指は同じため。
- 金管の運指番号・トロンボーンのポジションは PDF に記載があるので、それを正とする。木管は PDF に記載がないため、楽器メーカー公式の運指表（ヤマハ等）と、既存の運指表サイトの情報を突き合わせて転記する。**図版は参照のみ、転載・トレースはしない。**
- 各運指エントリに `confidence`（`verified` / `conflict`）と `sources` を持たせ、要確認箇所を管理する。

### 4.2 音高の表記

- 綴り付きの科学的ピッチ表記の文字列を使う：`"C4"`, `"F#5"`, `"Bb3"`, `"Fx5"`（ダブルシャープ）, `"Cb5"`。`C4` ＝ 中央ハ（MIDI 60）。
- `pitch.ts` に `parsePitch(str) → { letter, accidental, octave, midi }` と `midiToFreq(midi, a4 = 442)` を置く。基準ピッチは **A4 = 442 Hz**（日本の吹奏楽の基準ピッチ）。引数 `a4` は将来の F15（基準ピッチの変更）用。

### 4.5 楽譜データ `src/data/scales/<instrumentId>.json`

（以下の音高は形式を示す例。実際の値は PDF から転記する）

```json
{
  "instrument": "flute",
  "clef": "treble",
  "scales": {
    "C_major": {
      "keySignature": 0,
      "ascending":  ["C5","D5","E5","F5","G5","A5","B5","C6"],
      "descending": ["C6","B5","A5","G5","F5","E5","D5","C5"]
    },
    "C_minor": {
      "keySignature": -3,
      "ascending":  ["C5","D5","Eb5","F5","G5","A5","B5","C6"],
      "descending": ["C6","Bb5","Ab5","G5","F5","Eb5","D5","C5"]
    }
  }
}
```

- `keySignature`：正の数＝♯の個数、負の数＝♭の個数（0〜±7）。
- `ascending` 8音（主音〜オクターブ上の主音）＋ `descending` 8音（オクターブ上の主音〜主音）＝ 16音。最高音は両方に入る（PDF と同じく2回鳴らす）。**下行は上行の逆順ではない**（短調）ので必ず別々に持つ。
- 綴りは PDF どおり（例：嬰ト短調の上行7音目は `Fx`）。

### 4.6 運指データ `src/data/fingerings/<instrumentId>.json`

```json
{
  "instrument": "bb_trumpet",
  "family": "brass_valve",
  "range": { "lowest": "F#3", "highest": "C6" },
  "entries": {
    "60": [
      { "id": "std", "valves": [], "isPrimary": true,
        "confidence": "verified", "sources": ["pdf"] }
    ],
    "61": [
      { "id": "std", "valves": [1,2,3], "isPrimary": true,
        "confidence": "verified", "sources": ["pdf"] }
    ]
  }
}
```

キーは MIDI 番号（文字列）。ファミリー別のエントリ形：

| family | フィールド | 例 |
|---|---|---|
| woodwind | `keys: string[]`（テンプレートSVG内のキー ID） | `["L1","L2","L3","R1","R2","R3","Eb"]` |
| brass_valve | `valves: number[]`、Fホルンのみ `crook: "F" \| "Bb"` | `{ "valves":[1,2], "crook":"Bb" }` |
| brass_slide | `position: 1..7` | `{ "position": 4 }` |
| string | `string: "E"\|"A"\|"D"\|"G"`, `position: string`, `finger: 0..4` | `{ "string":"G","position":"I","finger":1 }` |

同じ MIDI 番号に複数エントリを持てる（代替運指）。`isPrimary: true` はちょうど1つ。

代替運指に `"hidden": true` を付けると、データには残したまま、アプリでは表示しない（「別の運指を表示」がオンでも出さない。2.6）。資料に載っていて転記はするが、生徒に見せないほうがよい運指に使う。主運指には付けない。

**B♭トランペットの転記**（M4）：

- 転記元は PDF の 5・6ページ「リップスラー」。段ごとに運指番号（0・2・1・12・23・13・123）が書かれ、その段の音はすべてその運指で吹く。各段の音と運指番号の組をすべてエントリにした（`sources: ["pdf"]`、`confidence: "verified"`）。音域は PDF に出てくる最低音〜最高音の `F#3`〜`C6`（31音、半音ずつすべてある）。
- 同じ音が複数の段に出てくるとき（例 E5 は 0・12・123 の段）、主運指（`isPrimary: true`）は「その段の中で低いほうから数えた位置（倍音の次数）が最も小さい段」の運指にする。ただし各段で上から2番目の音（第7倍音：B♭5・A5・A♭5・G5・G♭5・F5・E5。自然倍音のままでは音程が低い）は主運指にしない。この決め方で、一般的な運指（G♯5＝23、A5＝12、B♭5＝1 など）と一致する。
- `id` は主運指が `"std"`、代替が `"alt"`＋バルブ番号（例 `"alt13"`、なしは `"alt0"`）。
- 第7倍音の代替運指7つ（E5＝123、F5＝13、F♯5＝23、G5＝12、G♯5＝1、A5＝2、B♭5＝0）には `"hidden": true` を付ける。PDF のリップスラーには出てくるが、音程が低くなり生徒が混乱するため表示しない。
- 6ページの見出しは「第2倍音～第9倍音」だが、書かれている音は各段とも上行7音（第2〜第8倍音）。

### 4.7 テンプレートSVG `src/templates/<instrumentId>.svg`

- 楽器ごとに1枚、**手描きの独自図**。押さえる要素はすべて `id` を持つ `<circle>` / `<rect>` / `<path>`。
- 状態は CSS クラスで表現：`.key` が基本、`.key.pressed` が押下。木管の閉＝塗りつぶし・開＝白抜き、金管の押下バルブ＝塗りつぶし。
- トロンボーンはスライドの外形＋ポジション1〜7の目盛り。`position` の目盛りを強調表示。
- ストリングベースは指板（4弦＋ポジション目盛り）。該当弦・ポジションに指番号入りの丸を描く。
- viewBox は楽器ごとの図の形に合わせる（B♭トランペットは横長の `0 0 232 72`）。いま／つぎ枠・S3 は同じ SVG を、縦横比を保って大きさ違いで描く。いま／つぎ枠の中身は音名と運指図だけで（楽譜断片は廃止、2.6）、運指図は枠の幅いっぱいに描く。
- 押さえる要素は `class="key"` と `id` を持つ（`id` は1枚の中で重複しない）。要素に番号などの文字を書くときは `class="label"` の `<text>` をその要素の直後に置く。`src/render/fingering.ts` がテンプレートを文字列のまま読み、押さえる要素に `pressed` クラスを足す。いま・つぎ・S3 で同じ図を1ページに何度も置くので、描画時に `id` は `data-key` に置き換える。
- 色は CSS（`src/styles/fingering.css`）で、既存のテーマ変数から決める（ダークモードにも対応）。押していない要素は背景色（`--color-bg`）の上に輪郭だけ、文字は輪郭と同じ色（`--staff-ink`）。押している要素は塗りつぶし、文字は白抜き（背景色。`.key.pressed + .label`）。色だけでなく塗りでも区別する。線の太さは図の寸法に合わせてテンプレートに書く。
- 金管（バルブ）の押さえる要素の ID は `v1`・`v2`・`v3`（ユーフォニアム・チューバの第4バルブは `v4`）。
- 1枚の図に描くのは運指1つ。いま／つぎ枠は主運指、S3 は選んでいる運指（既定は主運指。「別の運指を表示」がオンのときだけ代替運指に切り替えられる。2.6）。`hidden: true` の運指（4.6）は、データにあっても図に描かない。
- B♭トランペット（`bb_trumpet.svg`）：3つのバルブを横一列の円で表し、各円の中央に番号 1・2・3 を書く。円ひとつで「どのバルブか」と「押すかどうか」が分かり、小さく表示しても読み取れる。直径 64、円どうしの間隔 16（直径の 0.25 倍）、線の太さ 6（直径の約 9%）、番号の文字の大きさ 36（太字）。既存の運指表は参照せず、この寸法の決まりから作った。375×812 では、円の直径が「いま」枠で約 49px、「つぎ」枠で約 38px、S3 で約 88px になる。

木管テンプレートのキー ID 規約（例：フルート）

```
Th, ThBb       左手親指キー（B、B♭レバー）
L1, L2, L3     左手 人差し指〜薬指
GsL            左手小指 G♯キー
R1, R2, R3     右手 人差し指〜薬指
Tr1, Tr2       トリルキー
Eb             右手小指 D♯(E♭)キー
LowCs, LowC, LowB   右手小指 足部管キー
```

クラリネット・サックス・オーボエ・ファゴットも同じ方針で、各楽器のキー ID 一覧を `templates/README.md` に定義してから運指データを転記する（ID の食い違いを検証スクリプトで検出する）。

## 5. 五線譜の描画仕様

VexFlow 等の記譜ライブラリは使わず、`src/render/staff.ts` で SVG を生成する。スケールに必要なのは 符頭・符幹・臨時記号・調号・音部記号・加線 のみ。

- 音部記号・調号・臨時記号・符頭は、SMuFL 準拠の音楽フォント **Bravura**（Steinberg、SIL Open Font License 1.1）のグリフを SVG の `<text>` で描く。フォントは `public/fonts/Bravura.woff2` を `@font-face` でローカル読み込みし（CDN は使わない）、Service Worker でプリキャッシュしてオフラインでも表示する。ライセンス文は `public/fonts/OFL.txt`。
- 符幹・五線・加線は自前のパスで描く。寸法は Bravura の推奨値（メタデータの engravingDefaults と anchor）に合わせる。

### 5.1 寸法

- 五線の線間隔 `S = 10`（SVG 単位）。段の高さは線5本＋上下に加線4本分の余白＝ `S × 12`。SMuFL の決まりにより、グリフのフォントサイズは `4S`（1em ＝ 線間隔4つ分）。
- 1段の横幅は `viewBox` で `500`（`50S`、5.7）。表示の幅は `100%` で、親要素に合わせて拡縮する。左から順に：
  - 音部記号（グリフの幅：ト音 `2.684S`、ヘ音 `2.736S`）。
  - 調号。1つ目は音部記号の右端から `0.42S` 空ける（ト音・ヘ音とも同じ）。記号1個あたり「グリフの幅＋`0.2S`」（♯ 約 `1.2S`、♭ 約 `1.1S`）。
  - 拍子記号（上段のみ、5.6）。
  - 音符8個を 5.7 の規則で配置。臨時記号は符頭の左端から `0.3S` 離して置く。4拍ごとの小節線と段の終わりの線（5.6）。
- 符頭は音価ごとに Bravura の `noteheadWhole`（全音符、幅 `1.688S`）・`noteheadHalf`（二分音符、幅 `1.18S`）・`noteheadBlack`（四分音符、幅 `1.18S`）を使い、音符の位置を中心に置く。
- 符幹は太さ `0.12S`。SMuFL の anchor に合わせ、上向きは符幹の右端を符頭の右端（`stemUpSE`：中心から `0.168S` 上）、下向きは符幹の左端を符頭の左端（`stemDownNW`：中心から `0.168S` 下）に付ける。
- 符幹の向き：第3線（中央線）上の音と、それより高い音は下向き。中央線より低い音は上向き。
- 符幹の長さ：符頭の中心から `3.5S`。ただし `3.5S` では第3線に届かない音（五線から離れた音）は、先端を第3線にそろえる（長さは第3線までの距離になり、遠い音ほど長い）。PDF の記譜で実測済み：トランペット譜 5ページの A3・A♭3（`4.0S`）・G3（`4.5S`）・F♯3（`5.0S`）、6ページの C6（`4.0S`）、トロンボーン譜 5〜6ページの第3線から `4.0〜5.5S` 上の音は、いずれも先端が第3線にそろっている。
- 加線は符頭の左右に `0.4S` はみ出す長さで引く（線端は丸めない）。
- 線の太さは Bravura の推奨値（engravingDefaults）に合わせる：五線 `0.13S`、加線 `0.16S`、符幹 `0.12S`。

### 5.2 音符の縦位置

`letter` と `octave` から「五線上の段（staff step）」を求め、音部記号ごとの基準（ト音記号：第1線＝E4、ヘ音記号：第1線＝G2）から y 座標を計算する。五線の外に出る音には加線を引く（第1線より下、第5線より上、2段ごと）。

### 5.3 臨時記号の表示ルール（PDF の見た目を再現）

音符の左に臨時記号を描くのは次のいずれか：

1. その音の変化記号が、調号でその文字に指定されている変化記号と**異なる**とき（例：ハ短調の上行 A♮・B♮）。
2. 同じスケール内で、その文字に**直前と異なる変化記号**が付いたとき（例：ハ短調の下行 B♭・A♭は調号どおりだが、直前に ♮ があったので ♭ を明示する）。

このルールで PDF の記譜（上行の ♮／♯、下行の ♭／♮ の明示）が再現できる。ダブルシャープ（`x`）にも対応する。

### 5.4 ハイライト

- 各音符を `<g class="note" data-index="i">` で包み、`current` / `next` クラスで色分け。
- `current`：符頭・符幹を強調色（例 `#d9480f`）、背景に角丸の矩形。`next`：同色の淡い版。
- 色はテーマ変数（CSS custom properties）で管理し、ダークモードにも対応する。

### 5.5 楽譜断片（廃止）

いま／つぎ枠に置いていた「5線＋符頭1つ」の楽譜断片は、M4 の実機確認で小さすぎて読めなかったため廃止した（2.6）。音の高さは五線譜のハイライトで示す。

### 5.6 拍子記号・小節線・終止線

**PDF の実測**（トランペット譜 2・3ページ、スケール 24 行）：

- 拍子記号はない。行の頭は音部記号と調号だけ（1ページのロングトーン等は 4/4・2/4 だが、スケールのページには拍子がない）。
- 全音符で、上行8音と下行8音（最高音を2回）の1行16音。小節線は上行と下行の境目に1本だけ。
- 行の終わりは細い小節線1本で、終止線ではない（ページの最後の行も同じ）。

**アプリの記譜**：メトロノーム（1拍＝四分音符、カウントイン1小節4拍）に合わせ、**4/4 拍子**で書く（PDF にはない、アプリとしての決定）。

- 拍子記号：4/4。上段の調号の右に置く（調号がない調は音部記号の右）。一般的な記譜と同じく最初の段（上段）だけに描き、下段には描かない。Bravura の `timeSig4`（U+E084、幅 `1.8S`、高さ `2S`）を2つ重ね、上の「4」は第4線、下の「4」は第2線を中心に置く。調号の最後の記号との間は `0.5S`。その後の音符の位置は 5.7。
- 小節線：4拍ごとに引く。1小節の音符数は **全音符 1／二分音符 2／四分音符 4**。1段が8音なので、どの音価でも段の終わりが小節の区切りと一致する（1段あたり 8／4／2 小節）。
- 小節線の位置と形：位置は 5.7 の規則による。第1線から第5線まで、太さ `0.16S`（Bravura の thinBarlineThickness）。
- 段の終わり：上段は細い小節線。下段は最後の音の後に**終止線**（細い線 `0.16S`＋間隔 `0.4S`＋太い線 `0.5S`。Bravura の thinBarlineThickness・thinThickBarlineSeparation・thickBarlineThickness）。太い線の右端を五線の右端にそろえる。音符は、段の終わりの線のぶんを空けて並べる（5.7）。
- 小節線・終止線の色は五線と同じ。

### 5.7 音符の間隔

**PDF の実測**（トランペット譜。距離はインクの端から端、単位は線間隔 `S`）：

| 項目 | スケール（2・3ページ、全音符、24 行） | リップスラー（5・6ページ、4/4・3/4、21 段） |
|---|---|---|
| 1音目の位置 | 各行の上行の小節を縦にそろえた配置。1音目の位置は調号の数によらず同じ（調号→1音目は 9.6〜1.9） | 拍子記号の右端→1音目の符頭 **2.2**（臨時記号付きは臨時記号が 0.7〜1.1） |
| 音符の間隔（符頭の左端→次の符頭の左端） | 上行 5.69。下行は行の幅に合わせて 5.8〜6.5 | 四分音符 6.0〜11.1（行の幅に合わせて伸びる） |
| 音符の右端→小節線 | 音符の間隔 − 符頭の幅 ＋ **約 0.5** | 同じ（音符の間隔 − 符頭の幅 ＋ 約 0.5） |
| 小節線→次の符頭 | 4.15（縦にそろえる配置のため） | **1.4**。臨時記号付きは臨時記号が小節線から 0.35〜0.8、符頭は 1.5〜2.1 |
| 臨時記号 | 付いても符頭の間隔は変わらない（臨時記号は前の音符とのすき間 4.4 に収まり、すき間が 3.0〜3.6 になる） | 同じ |
| 音価 | ― | 同じ段の中で、二分音符の間隔は四分音符の **1.62 倍**（1.61〜1.69）。四分休符は四分音符と同じ |

行の幅に合わせて伸びるのは「音符の間隔」だけで、拍子記号の後・小節線の前後の間隔は、どの段でも変わらない。

**アプリの規則**（`src/render/staff.ts` の `layoutNotes`）：

- 最初の符頭：拍子記号（下段は調号、調号がなければ音部記号）の右端から `2.2S`。最初の音符に臨時記号が付くときは、臨時記号と前の記号のすき間が `0.7S` 以上になるよう符頭を右へずらす（♯・♭・♮ なら `2.2S` のまま収まる）。
- 音符の間隔（符頭の左端→次の符頭の左端）は1段の中で一定。1段の音符は同じ音価なので、段の終わりの線に最後の音符の間隔がちょうど届くように、段の幅から決める（PDF と同じく、伸び縮みするのは音符の間隔だけ）。音価による違い（1.62 倍）は、1段に1種類の音価しかないアプリでは、この決め方で吸収される。
- 小節線：小節の最後の符頭の左端から「音符の間隔 ＋ `0.5S`」の位置に小節線の左端。小節線の右端から次の符頭まで `1.4S`。次の音符に臨時記号が付くときは、臨時記号と小節線のすき間が `0.4S` 以上になるよう符頭を右へずらす。
- 段の終わりの線（細い小節線・終止線）の左端も、最後の符頭の左端から「音符の間隔 ＋ `0.5S`」。
- 臨時記号が付いても音符の間隔は変えない。
- ハイライトの背景（5.4）は、音符（臨時記号を含む）の左右に `0.4S` ずつ広げた範囲。

**段の幅**：`500`（`50S`。`STAVE_WIDTH`）。

- 幅 375px の画面いっぱいに表示すると 1線間は約 `7.5px`（画面の左右に 16px ずつ余白をとる 343px なら約 `6.9px`）。
- 決め方：幅 500・480・400 の3案を、スマホの実機を譜面台に置いた距離で見比べて 500 に決めた（開発用の比較ページ `dev/widths.html`）。
- 幅 500 なら、調号7つの全音符で、上段（拍子記号あり）の小節線の直後の音符2つに臨時記号が付いても（♯7 はダブルシャープ、♭7 はナチュラル。調号7つの短調の上行で起こる形）、ト音記号・ヘ音記号とも PDF どおりの間隔で収まる（テストで確認）。幅 480 では ♯7 の全音符が、幅 400 ではハ長調の全音符でも収まらない。

**収まらないときの縮め方**（幅 500 のスケールでは起こらない。幅を変えたときのための規則）：

- 「最小の間隔」＝ 符頭の幅 ＋ `0.5S`。小節の中で、次の音符に臨時記号が付くときは、さらに「`0.3S` ＋ 臨時記号の幅」を足す（段の中で最も大きい値をとる）。
- 上の規則で求めた音符の間隔が最小の間隔を下回るときだけ、固定の間隔を縮める。縮める間隔と下限（PDF の値のおよそ半分）は次のとおり。
  - 最初の符頭の前：`2.2S` → `1.1S`
  - 小節線の前：`0.5S` → `0.25S`
  - 小節線の後：`1.4S` → `0.7S`
  - 臨時記号が付くときのすき間：最初の音符は `0.7S` → `0.4S`、小節線の直後は `0.4S` → `0.2S`
- すべての固定の間隔を同じ割合 `k`（0〜1）で縮める：`間隔 ＝ 下限 ＋ k ×（PDF の値 − 下限）`。`k` は、音符の間隔がちょうど最小の間隔になる値とする（音符の間隔は `k` の一次式なので、繰り返し計算せずに求まる）。音符の間隔は最小の間隔、段の終わりの線は段の右端のまま。
- 下限まで縮めても（`k = 0`）収まらないときは、下限の間隔と最小の間隔で並べ、段の右端からはみ出す（音符どうしを重ねない）。

## 6. オーディオ設計

`src/audio/` に集約。外部ライブラリなし（Web Audio API のみ）。

### 6.1 AudioContext のライフサイクル

- 生成は必ずユーザー操作（再生ボタンのタップ）内で行い、`resume()` する。iOS Safari の自動再生制限対策。
- ページが非表示になったら（`visibilitychange`）停止する。
- iOS はサイレントスイッチが ON だと Web Audio も鳴らない。S4 情報画面にその旨を記載する。

### 6.2 クリック音

- アクセント拍：1500 Hz の正弦波、30 ms、減衰エンベロープ。
- 通常拍：1000 Hz、20 ms。
- オシレーターは拍ごとに生成して使い捨てる（`start` / `stop` で時刻指定）。

### 6.3 参考音

- 波形は `triangle`（吹奏楽器に近い、耳障りでない）。ゲインは 0.25。
- エンベロープ：アタック 15 ms、リリース 60 ms（次の音と重ならないよう音価の 95% で減衰開始）。テンポが速く 95% からでは次の音に重なる場合（例：160 BPM の四分音符）は、減衰の開始を早めて次の音の頭で消えきるようにする。
- 参考音の ON/OFF（2.4）は再生中も切り替えられる。参考音は ON/OFF に関係なく予約し、参考音専用の出力（GainNode）のゲインで切り替える。OFF はその時点から 10 ms で消す（鳴っている途中の音も、予約済みの次の音も）。ON は次の音の開始から鳴らす（2.7-3「各音の開始時に鳴らす」。鳴っている途中の音を途中から鳴らさない）。
- 周波数＝ `midiToFreq(writtenMidi + instrument.transposition)`（基準ピッチ A4 = 442 Hz、4.2）。**実音で鳴らす。** 記譜音で鳴らすと B♭楽器等で教材の意図（全員同じ実音）と食い違う。

### 6.4 スケジューラ（先読み方式）

`setTimeout` 単体は使わない。標準的な「lookahead scheduler」を採用する。

```
tick 間隔      : 25 ms（setInterval）
先読み幅       : 100 ms
基準時刻 t0    : 再生開始時の audioCtx.currentTime + 0.05
拍 k の時刻    : t0 + k × (60 / bpm)
```

再生開始時に**イベント表**を一度だけ作る：

```ts
interface ScheduleEvent {
  beat: number;          // 0 から
  time: number;          // 絶対時刻（秒）
  kind: 'countin' | 'note' | 'beat' | 'end';
  noteIndex?: number;    // note / beat のとき 0..15
  accent?: boolean;      // カウントインの1拍目だけ true
  duration?: number;     // note のとき、音の長さ（秒）
}
```

- カウントイン：beat 0〜3、`countin`（beat 0 は accent）。
- 音 i（開始位置 s 〜 15）：beat = 4 + (i − s) × beatsPerNote、`note`。beatsPerNote は音価から（全4／二分2／四分1）。先頭から再生するときは s = 0。
- 音の途中の拍：`beat`（クリックだけ鳴らす。noteIndex はその音）。クリックは「拍」ごと、参考音は「音の開始」（`note`）ごと。途中の拍も1行ずつ持つので、どのクリックも先読み幅の範囲でだけ予約され、停止時に先の音が残らない。
- `end`：beat = 4 + (16 − s) × beatsPerNote。音は鳴らさない（最後の音が終わる時刻）。
- 時刻は拍ごとに `t0 + k × (60 / bpm)` で計算し、足し算を重ねない（長く再生しても誤差がたまらない）。

tick ごとに `time < currentTime + 0.1` のイベントを Web Audio にスケジュールし、既にスケジュール済みのものは飛ばす。

実装は `src/audio/scheduler.ts`（イベント表・進行度の引き当て・先読み）と `src/audio/player.ts`（AudioContext・スケジューラ・requestAnimationFrame・store をつなぐ再生の制御）に分ける。

### 6.5 テンポ変更（再生中）

**v1 では再生中（カウントイン中を含む）はテンポを変更不可とする。** テンポは再生開始時の値でイベント表を作る。将来対応する場合は、現在の音の開始時刻を基準に以後のイベント時刻を再計算する（未スケジュール分のみ）。

## 7. 同期設計（実装上の要）

### 7.1 単一の進行度

UI が参照する状態は **`progress: { noteIndex: number | null, phase: 'idle' | 'countin' | 'playing' | 'done' }` の1つだけ**にする。メトロノーム・五線譜ハイライト・いま／つぎ枠のすべてがこの値から導出される。`noteIndex` は、再生中・終了後は今の音、カウントイン中はこれから鳴らす最初の音（開始位置）、停止中は `null`。停止中の表示は、これに選んだ音 `selectedIndex`（2.5）を合わせて決める。

例外は拍に合わせた脈動（2.5・2.6）だけで、これは飾りなので `progress` ではなく拍の時刻 `beatClock`（7.2）から描く。どの音を表示・ハイライトするかは、脈動があってもなくても `progress` だけで決まる。

### 7.2 UI の更新タイミング

- オーディオのスケジュールと UI 更新を**分離**する。オーディオはイベント表の時刻どおりに先読みで鳴らす。UI は `requestAnimationFrame` ループで `audioCtx.currentTime` を読み、イベント表から「現在時刻に該当する noteIndex」を求めて `progress` を更新する。このとき、画面に使う時刻は `currentTime − outputLatency`（出力の遅延を差し引いた、耳に届いている時刻）とする。Bluetooth イヤホンなどで出力遅延が大きくても、ハイライトが音より先に進まない。`outputLatency` に対応しないブラウザでは `currentTime` のまま。音の予約には `currentTime` を使う。
- こうすると UI がどれだけ遅れても音はズレず、UI は常に「音に追いつく」形になる。`setTimeout` のコールバックで UI を更新してはいけない。
- `progress` が変化したフレームだけ DOM を更新する（毎フレーム描画しない）。

**拍に合わせた脈動**（2.5 五線譜のガイド、2.6 いま枠の枠線）：音とハイライトの同期を崩さないよう、次のように作る。

- 毎拍の処理はしない。再生開始時に `player.ts` が拍の時刻 `beatClock: { origin, beatMs }` を store に置く。`origin` はカウントイン1拍目が耳に届く時刻を、画面のアニメーションの時計（`performance.now()`・`document.timeline` と同じ基準、ミリ秒）で表したもの：`origin = performance.now() + (t0 − (currentTime − outputLatency)) × 1000`。`beatMs = 60000 / bpm`。停止・自動停止で `null` に戻す。
- 画面は `beatClock` が変わったときだけ、Web Animations（`element.animate`）で1拍の長さの繰り返しアニメーションを作り、`startTime = origin` にそろえる。以後の拍ごとの動きはブラウザに任せる（`setTimeout` も毎フレームの JavaScript も使わない）。
- 動かすのは、脈動用に重ねた要素（いま枠の枠線に重ねた輪 `.nn-pulse`、五線譜のガイドに重ねた矩形 `.note-pulse`）の `opacity` だけ。レイアウトを変えず、音の予約・`progress` の計算には関わらない。ガイドが次の音符に移ったら、重ねた矩形をその音符に移してアニメーションを作り直す（開始時刻は同じ `origin` なので拍の位置は変わらない）。
- 音の時計と画面の時計は、再生開始の直後に音の時計の進みが遅れるなどして少しずれることがある。音が切り替わったフレームで `origin` を計算し直し、25ms を超えてずれていたら `beatClock` を置き直す。
- 濃さ：いま枠の輪は拍の頭で `opacity 1`（輪は枠線の外側へ `4px` 太く、`14px` ぼかして光る）、五線譜の矩形（現在音の色）は `0.35`。どちらも拍の半分で 0 に戻る。値は `src/render/pulse.ts` の定数（輪の太さ・ぼかしは `src/styles/nowNext.css`）で調整する。M4 の実機確認で、控えめ（輪 `0.5`・外側 `2px`、矩形 `0.14`）では演奏中に分かりにくかったため、視界の端でも拍が分かる強さにした。
- `prefers-reduced-motion: reduce` のときは動かさない。
- 確認（M4 の実装時、PC の Chromium）：音が切り替わったフレームで、脈動は拍の頭から 1 フレーム程度（拍の 3〜7%）の位置にあった。再生中の 25ms 間隔のタイマーの遅れは、脈動あり・なしで差がなかった（強めた後も最大 28〜31ms。先読み幅 100ms の範囲内）。iPhone の実機確認（控えめな強さのとき）では問題の指摘はなかった。強めた後の確認は次の実機確認で行う。

### 7.3 いま／つぎの導出

```
phase = 'idle'    → now: なし,            next: 音0（選んだ音 s があれば now: 音s, next: 音s+1）
phase = 'countin' → now: なし（カウント）, next: 開始位置の音（noteIndex）
phase = 'playing' → now: 音i,             next: 音i+1（i=15 なら「おわり」）
phase = 'done'    → now: 音15,            next: 「おわり」
```

五線譜のハイライト（2.5）も同じ導出を使う：idle はハイライトなし（選んだ音があればその音を「現在」・次の音を「次」）、countin は開始位置の音を「次」、playing は now を「現在」・next を「次」、done は音15を「現在」のまま残す（「おわり」はハイライトしない）。

### 7.4 状態管理

小さなストア（`src/state/store.ts`）を自前で持つ。フレームワークは使わない。

```ts
interface AppState {
  instrumentId: InstrumentId | null;
  keyId: string;               // 既定 'C_major'
  bpm: number;                 // 既定 60
  noteValue: 'whole' | 'half' | 'quarter';  // 既定 'half'
  toneEnabled: boolean;        // 既定 true
  showAlternateFingerings: boolean;  // 「別の運指を表示」（2.6）。既定 false
  progress: Progress;
  selectedIndex: number | null; // 停止中に選んだ音（2.5）。「いま」に表示し、再生はこの音から始める
  beatClock: BeatClock | null; // 再生中の拍の時刻（脈動用、7.2）。停止中は null
}
```

端末に保存する設定は `src/state/settings.ts` が扱う。localStorage のキー `scale-fingering-nav:settings` に JSON で保存し、起動時に読み込んで `AppState` の既定値に上書きする。今は `showAlternateFingerings` だけ（調・テンポ・音価などは M5、F10）。保存がない・壊れている・localStorage が使えない（プライベートブラウズ等）ときは既定値のまま動き、例外でアプリを止めない。

`subscribe(listener)` で変更を通知し、各ビュー（設定行・五線譜・いま／つぎ枠・再生バー）が自分の関心部分だけ再描画する。

## 10. 検証

### 10.1 単体テスト（Vitest）

- `parsePitch`：`"C4"`→60、`"Bb3"`→58、`"Fx5"`→79、`"Cb5"`→71。
- 移調：各楽器の `transposition` を使い、記譜 C → 実音が期待どおり（B♭クラリネット C5 → B♭4 など）。
- 臨時記号ルール：ハ短調（上行 A♮ B♮、下行 B♭ A♭ に記号）、嬰ト短調（Fx）、ハ長調（記号なし）。
- スケジューラ：bpm=60、二分音符で、音 i の時刻が `t0 + (4 + 2i)` 秒になる。開始位置 s から再生すると、カウントイン4拍のあと音 s が `t0 + 4` 秒、音 i が `t0 + (4 + 2(i − s))` 秒で、16音目のあと終わる。
- 進行度の導出：時刻→noteIndex のテーブル引きが境界（音の切替瞬間）で正しい。

### 10.2 データ検証スクリプト `npm run validate`

全楽器・全調について次を機械的に確認し、失敗を一覧で出す。

1. `ascending` が 8 音、`descending` が 8 音（どちらも最高音を含む）。
2. 音列が、実音の調 ＋ 楽器の移調から理論的に導いた音列（長音階／旋律的短音階上行／自然短音階下行）と MIDI 番号で一致する。
3. 各音の MIDI 番号に運指エントリがあり、`isPrimary: true` がちょうど1つ。
4. 運指エントリの `keys` がテンプレート SVG に存在する ID のみで構成される（木管）。`position` が 1〜7（トロンボーン）。
5. 各音が楽器の `range` 内。

あわせて、運指データのファイルごとに次も確かめる：楽器 id・`family` が `instruments.ts` と一致、`range` の上下、エントリのキーが `range` 内の MIDI 番号、楽譜に出てこない音も含めて `isPrimary: true` がちょうど1つ・`id` が重複しない、`confidence` が `verified`／`conflict`、`hidden` が true／false で主運指に付いていない、金管（バルブ）の `valves` が 1〜4 の整数で `v<番号>` がテンプレートにある、`crook` は Fホルンだけ、テンプレート SVG があり押さえる要素の `id` が重複しない。楽譜データがあって運指データがない楽器も問題として出す。

### 10.3 実機確認チェックリスト

- iPhone Safari／Android Chrome の縦向きで、S2 がスクロールなしに収まる。
- 再生ボタン1回で音が出る（初回タップで AudioContext が有効になる）。
- 60 BPM・120 BPM で 1 分間再生し、クリックとハイライトの切替が体感でズレない。
- 画面を消灯→復帰しても表示が壊れない（停止状態に戻る）。
- 機内モードで再読み込みしても起動する（PWA）。
- いま／つぎ枠の運指図が、実際の奏者（各楽器1名以上）の確認を受けている（フェーズごと）。

## 11. 非機能要件
